# POC v4 — абляція механізму адаптивного вибору горизонту

## Мета та статус

Перевірити, чи є перевага **самого правила адаптивного вибору горизонту**, а не лише ефект зміни тривалості прогнозу. Це офлайн-дослід на синтетичних даних; не застосовувати результати як доказ готовності до польоту або навігації без GNSS.

## Дані та модель

Використано вже навчені моделі LSTM з POC v2 (один training seed), 4 незалежні валідаційні синтетичні траєкторії для калібрування і 12 інших синтетичних тестових траєкторій. Горизонти: 0,25; 0,5; 1,0 с. Прогноз видається кожні 5 відліків за частоти 20 Гц. Усі варіанти оцінюються на однакових моментах видачі прогнозу, з відповідними фактичними станами для обраного горизонту.

Адаптивне правило базується на EMA попередніх фактично дозрілих похибок; результат прогнозу не впливає на наступне рішення раніше, ніж настав його цільовий момент. Пороги `0.205458` і `0.558470` м збережено з валідаційного етапу v2.

## Основна перевірка політик

Порівняно `adaptive`, `fixed_0.25`, `fixed_0.5`, `fixed_1.0`, циклічний вибір та випадковий рівноймовірний вибір. Проста середня помилка між політиками з різними горизонтами **не є коректною підставою заявляти перевагу**. Тому попередньо визначена дослідницька функція втрат має вигляд:

`L = (position_error / CA_RMSE_val(h))² + λ (1 - h / 20)`

де `CA_RMSE_val(h)` — RMSE CA на валідаційних траєкторіях для горизонту `h` (у відліках), `λ` — умовна ціна короткого прогнозу. Для λ перевірено 0, 0,25, 0,5, 1,0. Вибір функції корисності **не має фізичного обґрунтування для реального керування**: це лише чітко визначений дослідницький критерій порівняння.

При λ=0,5:

| Політика | Середня функція втрат (менше — краще) | Середній горизонт, с |
|---|---:|---:|
| Fixed 0,25 s | 3,0929 | 0,2500 |
| Adaptive | 8,5672 | 0,5194 |
| Fixed 0,5 s | 10,5209 | 0,5000 |
| Random uniform | 13,6036 | 0,5800 |
| Cycling | 13,9858 | 0,5792 |
| Fixed 1,0 s | 28,1430 | 1,0000 |

Адаптивна політика виявилася кращою за фіксований горизонт 0,5 с **за заданою функцією втрат**, але гіршою за фіксований горизонт 0,25 с. Парний bootstrap за 12 польотами для порівняння adaptive minus fixed 0,5 при λ=0,5 дає середню різницю −1,9537; 95% CI приблизно [−4,58; 0,02], тобто нуль не виключений.

## Контроль часток горизонтів: matched-mix diagnostic

Щоб відокремити вибір **моментів** прогнозування від загальної частки горизонтів, для кожного польоту збережено набір вибраних адаптивною політикою горизонтів, але їхні часові позиції перемішано 300 разів. Для порівняння застосовано квадрат позиційної похибки, нормований на RMSE **LSTM** відповідного горизонту, визначений тільки за validation-польотами. Це інша метрика, ніж попередня utility-функція.

- Adaptive mean normalized loss: **1,2608**.
- Shuffled with same horizon counts: **1,2792**.
- Adaptive − shuffled: **−0,01835**.
- 95% bootstrap CI за 12 польотами: **[−0,1344; +0,0581]**.

Інтервал включає нуль, тому **немає достатнього підтвердження**, що правило адаптації систематично краще призначає горизонти конкретним моментам часу. Shuffled mixed-horizon comparator — ретроспективний діагностичний контроль; його не слід трактувати як причинну онлайн-політику.

## Обмеження

1. Є лише одна навчена LSTM на кожен горизонт. Інтервали bootstrap за польотами не враховують невизначеність навчання.
2. Синтетичний генератор близький до моделі сталого прискорення, що може сприяти CA.
3. У різних горизонтах відрізняється час отримання еталона. Для обраного горизонту оцінюється саме відповідна ціль, не ідентичний кінцевий момент.
4. Не перевірено GNSS outage, дрейф IMU, невідповідність тренувального та реального розподілів.
5. Параметр λ та саму функцію корисності потрібно обґрунтувати до претензії на практичну оптимальність політики.
6. Порівняння за 12 незалежними тестовими траєкторіями має обмежену статистичну потужність.

## Висновок і наступний етап

Перевага адаптивного вибору горизонту **не доведена**. Водночас v4 реалізує коректніший протокол оцінювання політик, парний контроль на рівні траєкторії і діагностику переваги щодо розміщення прогнозів у часі. Для наступної перевірки рекомендуються: (а) політика, що оцінює очікувану помилку кожного горизонту з доступних ознак руху, (б) оцінювання на кількох seed навчання, (в) незалежніші генератори та реальні дані, (г) попередньо фіксована функція корисності.
